# e1 — #116 The daemon connection icon in the UI is above the popped out note

## Reproduced

`web/render/helpers/harness.ts`, the `notes` fixture and the built bundle). The daemon is healthy
(the fixture's live socket). It pops out `notes-long`'s note, drags the panel so it covers
`#connection-status`, then reads `elementFromPoint` at the readout's centre and the computed
position and z-index of both elements:


The daemon is connected (`data-health="ok"`) and the banner is hidden, yet the 14×14 readout
(a green dot) draws over the panel's header and is the click target there.

## Holds

The entry holds as written, but the behaviour was decided on purpose, so the bug sits in the
scope of that decision. The z-order comes from an **accepted** ADR, kb:adr/notes-banner-above-popped-panel
(2026-11-04, plan popped-out-note-enhance, commit b5c45d34). The ADR puts "the daemon-down banner
and the masthead's connection readout" above the popped panel, so that a placed panel never hides
an outage. The readout was added only "for consistency" (decision.md, Outcome). The ADR's whole
rationale is about the outage, but the CSS applies the rule in every state. So the readout also
covers the panel while the daemon is connected, which is the case filed (session idle, daemon
up). The render test that pins the ADR (`web/render/notes-places.spec.ts:489`) checks only the
daemon-down state. docs/features/notes/spec.md:62-64 and docs/design/design-system.md:346-349
repeat the unconditional wording.

## Cause

`web/src/style.css:510-513`: `#connection-status { position: relative; z-index: 46; }`. This
puts the readout above `.npanel` (`web/src/style.css:4966-4968`, `position: fixed; z-index: 45`)
whatever its `data-health` is. The masthead creates no stacking context of its own, so 46 beats
45 at the root. The rule was added in b5c45d34 to carry out decision A of the
banner-above-popped-panel debate. That debate concerned the outage only, but the selector does
not depend on the outage. `.banner` (`style.css:660-662`, also 46) is shown only while the daemon
is down (`[hidden]` otherwise), so it causes no healthy-state overlap.

A likely minimal fix: drop the z-index from the bare `#connection-status` rule and raise the
readout only while it reports the outage, with
`#connection-status[data-health="down"] { z-index: 46; }`.
`web/src/features/connectionhealth.ts:21-25` sets `down` exactly when the readout says
`musterd unreachable — reconnecting…`. That state matches the banner through the 3 s window
(kb:adr/connection-health-dot). The `pending` states are `connecting…` before the first hello
and the update restart. In those states the panel would sit above the readout, and the ADR's
outage argument does not cover them.

## Questions

1. The filed expectation contradicts an accepted ADR, kb:adr/notes-banner-above-popped-panel,
   which deliberately puts the connection readout above a popped panel. Which do you want?
   - **(a)** The readout draws above the panel only while it shows the outage
     (`data-health="down"`). The panel covers it when connected, connecting, or during the update
     restart. The banner stays above the panel. This keeps the ADR's honesty argument and fixes
     #116. It is the recommended option, and it needs a superseding ADR.
   - **(b)** The panel always draws above the readout, and only the banner stays above it. While
     down, a panel at the top right then hides the red dot, but the full-width banner still says
     musterd is unreachable.
   - **(c)** Keep the current order and close #116 as working as decided.

## Answers

Developer, 2026-11-06, verbatim: "1a"

Resolved: option (a) — the connection readout draws above a popped panel only while it shows the
outage (`data-health="down"`); the daemon-down banner stays above the panel; otherwise the popped
panel covers the readout. Carries a new ADR superseding `kb:adr/notes-banner-above-popped-panel`,
and the notes spec and design-system sentences reconciled to say the order is conditional.
