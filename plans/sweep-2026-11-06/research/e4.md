# e4 — Add restart option to right click menu (#119)

## Reproduced

Web (card menu has no Restart item, live or ended) — a throwaway Vitest probe kept in the scratchpad, run against the real `railmenuitems.ts`; the repo was not changed:

```
$ cd web && npx vitest run --config $SCRATCH/probe/vitest.probe.config.mjs
alive=true labels: ["Mark as unread","Stop…","Remove…"]
alive=false labels: ["Mark as unread","Resume","Remove…"]
   × card menu, alive=true, offers Restart
   × card menu, alive=false, offers Restart
AssertionError: expected false to be true // Object.is equality
 Test Files  1 failed (1)
      Tests  2 failed (2)
```

Daemon: the only restart endpoint refuses a session that is not behind. The existing guard passes, and it asserts exactly that:

```
$ go test ./internal/server -run TestRestartSessions_ClassifiesEachListedID -v -count=1
--- PASS: TestRestartSessions_ClassifiesEachListedID (0.05s)
```

(`internal/server/restart_test.go:272`: `assert.Equal(t, []int64{999999, dead, noVersion, current, newer, unbound}, got.Skipped)`. An alive, idle session that is current, newer than installed, or has no version is `skipped`, so nothing restarts.)

## Holds

Held as written, but the scope is wider than "one more menu item". The menu has no Restart. Also, the daemon's only restart path (`POST /api/sessions/restart`) is gated on `claudeVersion.behind`, so a session on the latest version cannot be restarted manually. The spec says so on purpose: `docs/features/actions/spec.md:65` reads "only as one batch from the masthead readout … there is no per-session restart and no cancel".

## Cause

`internal/session/restart.go:105`: `ClassifyRestart` returns `RestartSkip` for `!sess.Alive`, `sess.ClaudeVersion == ""`, `!sess.ClaudeBehind` or `sess.ClaudeSessionID == ""`. `SetRestartPending` (`:121`) refuses a non-behind mark with `ErrNotBehind`. `settleClaudeBehindLocked` (`:60`) clears any `restartPending` that is not behind, and the wire invariant (`docs/protocol.md:1414`, `restartPending ⇒ alive && claudeVersion != null && claudeVersion.behind`) writes that rule into the contract. The handler (`internal/server/restart.go:136-144`) only does done/queued for those classes. On the web side, `cardMenuItems` (`web/src/features/railmenuitems.ts:63-82`) builds only Stop…/Resume and Remove…, and the accepted ADR `kb:adr/rail-card-menu-read-toggle-first-move-to-last` fixes the menu's contents and order. So a manual restart cannot reuse the existing message unchanged. It needs either a new per-session endpoint, for example `POST /api/sessions/{id}/restart`, or a new field on `sessions.restart-many`, for example `{"ids":[…], "force": true}` / `"reason":"manual"`, that bypasses the version gate. If a busy session is queued, it also needs `restartPending`'s invariant loosened, plus the reload/hold rules (`kb:adr/restart-pending-marks-held-until-installed-known`) reworked for a mark that is not version-driven. The Stop-then-Resume halves (`restartLocked`, `internal/server/restart.go:104`) can be reused unchanged.

## Work type

## Proof

- Logic, web-tests: `web/src/features/railmenuitems.test.ts`, "card menu offers Restart… on a live bound session". It asserts that `cardMenuItems({alive:true, claudeSessionId:"x", …}).actions` contains the Restart label. It is red today: the labels are `["Stop…","Remove…"]`.
- Logic, daemon-tests: `internal/server/restart_test.go`, e.g. `TestRestartSession_ManualRestartsACurrentFreeSession`. A free, idle, non-behind (`current`) session gets the manual request → `done`, killed once, resumed on the same row with the same `claudeSessionId`. It is red today because `current` is `skipped` (see the assertion at `:272`). It needs a second case for a busy session, whose outcome (queued, interrupted, or refused) is a decision; see Questions.
- Journey, e2e-specs: `web/e2e/rail-menu.spec.ts` (or `claude-restart.spec.ts`). Right-click a live card → Restart… → confirm → the card goes `alive:false`, then `alive:true` on the same row. This is a cross-daemon journey, so it is E2E.
- Render, render-tests: `web/render/rail.spec.ts`, a menu fixture showing the item's position and its disabled state while disconnected or busy.

## Route

`not-small-track: protocol`. The existing `POST /api/sessions/restart` cannot be reused unchanged, because its version gate is the contract (`kb:anchor/sessions.restart-many`, the `restartPending` invariant). It also needs a spec change: `actions/spec.md` states there is no per-session restart, and the accepted card-menu ADR has to be superseded. The menu item itself is one more item in an existing menu, not a new UI surface. It probably needs a confirm dialog, which can reuse the existing confirm pattern (`render/confirm.ts`), like Stop… and Remove….

## Questions

1. **Which states allow it?** The proposal is any live session with a bound `claudeSessionId`, since Resume needs one. It would be omitted for ended sessions, which already have Resume, and for unbound sessions (trust prompt / bypass warning, where nothing can be resumed). Is that right? Should a session that is behind also use this path, so the menu item is version-agnostic?
2. **A working, busy session:** (a) queue it until it is free, like the version restart (this loosens the `restartPending` invariant and the reload/hold rules); (b) stop it now, interrupting the turn, behind a confirm that says so (simplest, and matches Stop…); or (c) disable the item while busy? The motivating case is reloading an MCP.
3. **A queued manual mark across a daemon restart:** if (a), does it survive like the version mark, or is it dropped?
4. **Endpoint shape:** a new `POST /api/sessions/{id}/restart`, or a `force`/`manual` field on the batch endpoint? Should the Select-mode selection menu also offer it?
5. **Placement and label:** "Restart…" (with confirm) next to Stop…, in the actions group?

**Overlap with #118** ("started" session eligible for the restart-onto-latest offer): both entries share the restart domain, `internal/session/restart.go` (`restartFree`/`ClassifyRestart`) and `internal/server/restart_test.go`. The web side of #118 is `web/src/features/restartplan.ts` (`isFree`, offer filter at `:18-23`), which #119 need not touch. Note that the daemon already queues a behind `started` session (the test above lists `busy["started"]` as `queued`). #118's gap is probably upstream, e.g. `claudeVersion` being null or `claudeSessionId` unbound for a just-started session, so it is skipped and never offered. If both run, put them in the same batch or plan, since they edit the same daemon files and the same `docs/protocol.md` section.

## Answers

Developer, 2026-11-06, verbatim:
"4:
- Yes
- Warn and ask for confirmation
- It would change to Restart All and then any appropriate warning"

Resolved: (1) the item is offered on any live session with a bound Claude conversation (not ended,
not unbound); (2) a working/busy session gets a warning and a confirm, then is restarted (the turn is
interrupted), not queued; (3) with several sessions selected the item becomes "Restart All", with the
appropriate warning for any busy ones. Route stays `not-small-track: protocol` — a sweep never
changes the daemon↔UI protocol — so e4 is not in this sweep; these answers carry to `/spec` or
`/plan-work` for #119.
