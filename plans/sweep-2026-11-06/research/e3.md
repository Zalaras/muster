## Holds

The entry holds, but its scope is different from how it is written. A behind `started` session *is* offered: `isOfferedRestart` ignores
state, and the confirm dialog lists it under "Restart when free" with reason `starting`. It is
**queued, not restarted**. A queued restart fires only on a transition to free (idle with 0 tasks,
or failed). A just-started session reaches that only after the developer sends a prompt and the
turn ends. So in practice it is never upgraded while it sits unused, which is the symptom the developer
reported. This is not a bug. It is the documented rule.

## Cause

`internal/session/restart.go:21`, `restartFree()` returns `(State == StateIdle && BackgroundTasks == 0) || State == StateFailed`.
`ClassifyRestart` (restart.go:96) uses it to pick `RestartNow` vs `RestartQueue`, and `restartDue`
(restart.go:25) uses it to fire the queue. The web mirrors the rule in `isFree`
(`web/src/features/restartplan.ts:18`) to split the dialog's "now" and "when free" lists. The rule
comes from an **accepted ADR**: `kb:adr/restart-busy-sessions-queued-until-free` ("Free is `idle`
with `backgroundTasks == 0`, or `failed`"). It also appears in the protocol contract (`docs/protocol.md:606`
"A session is **free** when …") and in `docs/features/actions/spec.md:65`. Plan
`restart-latest-claude` D5 lists `started` explicitly among the busy states. The fix reverses
an accepted decision.

A second risk, unmeasured: restart is Stop and then `claude --resume <claudeSessionId>`
(`kb:adr/restart-is-stop-then-resume-in-place`). A session in `started` has had no prompt since
SessionStart. That covers both a fresh launch and a post-`/clear` rebind, which also lands in `started`
(machine.go:187). Its transcript may not exist yet. `kb:fact/resume-restores-model-and-mode-except-plan`
records that unknown ids exit 1. If Claude Code writes no transcript before the first prompt, the
Resume half fails and the session is left ended. No fact record says whether a promptless session's
id can be resumed, so this needs an `/interface-probe` before any change. If it cannot be resumed,
a started session needs a fresh launch in place instead of a resume. That would be a new restart path.

## Proof

- **Logic (unit), daemon-tests**: `internal/session/restart_test.go`,
  `TestClassifyRestart_EveryStateAndCondition/started/behind`, with `restartStates()` `started` set to
  `free: true`. Today it fails with `assert.Equal(RestartNow, RestartQueue)`. Its sibling, the
  queue-fires-on-free invariant (`restartDue`), should cover `started` the same way. A session that is
  already pending and is in or enters `started` (for example after a `/clear`) fires.
- **Logic (unit), web-tests**: `web/src/features/restartplan.test.ts`, `isFree` row `started`

  (e2e-specs). That goes beyond the small track.

## Route

`not-small-track: protocol`. The change redefines **free** in `docs/protocol.md` §restart-many,
so the `done`/`queued` outcome for a started session changes, and it supersedes an accepted ADR. If
the developer rules that the protocol sentence is a doc-only consequence of a new ADR, and the probe
shows a promptless session can be resumed, it shrinks to `fix` (two predicates, two test rows, ADR,
spec and protocol sentence).

## Questions

1. **Reverse the accepted ADR?** `kb:adr/restart-busy-sessions-queued-until-free` (accepted
   2026-11-04, the developer's choice B) and plan D5 class `started` as busy. Should `started`
   (with 0 background tasks) become free? The fix would be a superseding ADR.
2. **Is a promptless session resumable?** This is unmeasured. Restart resumes by `claudeSessionId`. A just-started
   or just-`/clear`ed session may have no transcript, and `--resume` of an unknown id exits 1. Run
   `/interface-probe` first. If it is not resumable, the developer must choose between a fresh launch in place for a started
   session (a new restart path, likely `/orchestrate`) and leaving started queued.
3. **Protocol change routing.** Should a semantic edit to the definition of free in `docs/protocol.md` go
   through `/orchestrate`, or does it ride a `/fix` as doc reconcile?

**Overlap with #119** (restart in the rail card's right-click menu): #119 adds a per-session

ADR set. If both go ahead, they belong in the same batch or plan.
