**Verdict: nothing found.** Muster misses no interrupt signal that Claude Code 2.1.328 writes.

## Holds

The symptom holds, but with a different cause and scope. The cause is the accepted
early-interrupt gap (kb:adr/lifecycle-early-interrupt-gap-accepted), not a Muster defect.
- An Esc during the first request or the first thinking block of a typed prompt leaves no
  signal at all (Probe 2). With Opus 5.5's long thinking, that window is many seconds.
- Every Esc that Claude Code marks is caught:
  - mid-tool (Reproduced items 1–3);
  - mid-stream;
  - in a task-notification turn (Probe 3);
  - stopping a background agent, which is closed by hooks (Probe 1).
- "Running a script" most plausibly means a background task from the previous turn. The
  snapshot shows no tool call in the interrupted turn.
- This is not #96/#110 (kb:adr/lifecycle-background-tasks-count-not-state).

## Cause

`internal/session/interrupt.go:46-52` lands idle only on a `[Request interrupted by user…` line.
Claude Code 2.1.328 writes none for an Esc before a typed prompt's first assistant line
(kb:fact/interrupt-during-thinking-leaves-no-trace). It fires no hook and changes nothing on the
status line either. The hard rule bars terminal output as a state source, so the daemon has
nothing to read. This is by decision (kb:adr/lifecycle-early-interrupt-gap-accepted), not a code
defect.
