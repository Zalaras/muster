# Decision: compact-sessionstart-left-id

**Outcome**: B. The compaction end is monotonic. A `SessionStart{source:"compact"}` carrying a `session_id` this session has already left is applied as a reordered straggler, with no rebind and no reset. The forward-rebind-or-straggler decision stays in `Apply`'s single guarded branch (kb:adr/ingest-monotonic-rebind), and `applyCompactionEnded` no longer makes it.
**Reached by**: consensus. advocate-a conceded in turn 3.
**Decisive argument**: advocate-b, turn 2. Measured facts fix what a left id can mean for each source. `startup` and `clear` never carry one (kb:fact/clear-mints-new-session-id). `resume` legitimately can. `compact` carries "the **same** `session_id`" as its own `PreCompact` (kb:fact/compact-hook-sequence, step 3), so for compact a left id can only be the reordered straggler the ADR was written for. A backwards rebind would also leave the session stuck on the old id: `AliveByClaudeSessionID` would miss the new conversation (`internal/session/manager.go:573-585`), letting a resume-from-list breach kb:adr/launch-resume-one-alive-row-per-claude-session, and `Resume` would reopen the pre-clear conversation (`internal/server/launcher.go:538`).
**Dissent to honour**: advocate-a's turn 1 point stands as history. `main` already let every non-resume `SessionStart` rebind on a mismatched id, so the guard's coverage of `startup`/`clear` binds is unchanged here. Those sources never carry a left id, so this needs no follow-up.
**Landed in**: plans/state-issues/plan.md (REQ-9 Amended), docs/protocol.md (`state.transitions` compact `SessionStart` rows), docs/adr/lifecycle-compaction-end-monotonic.md (proposed).
