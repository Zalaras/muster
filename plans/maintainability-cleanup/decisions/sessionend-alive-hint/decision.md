# Decision: sessionend-alive-hint

**Outcome**: B. The `KindDeathHint` arm is deleted, so a non-clear `SessionEnd` no longer writes `alive`/`endedAt`. `alive` comes from the pane check alone, as the accepted kb:adr/lifecycle-liveness-from-pane-existence and kb:adr/lifecycle-alive-flag-not-a-state already say. The protocol rows and prose that describe the hint are corrected to match.
**Reached by**: consensus. advocate-a-sessionend conceded in turn 2.
**Decisive argument**: The hint is a writer of `alive=false` with no guard, and it keeps running through the shutdown window that kb:adr/lifecycle-liveness-writes-stop-at-shutdown closed for the poll and the PTY nudge. `shutdownGracefully` stops the poll first (`cmd/musterd/onexit.go:48`), then waits up to 10 s in the `-on-exit=ask` prompt before HTTP shutdown (`:96`). `Apply` has no `stopped` guard. A `/exit` in that window persists `alive=0`, and the next boot's reconcile deletes the paneless `alive=0` row, which loses Resume. That is the failure the shutdown ADR measured (8/10). B's cost is at most 5 s of stale "alive" (the poll interval), and only when no terminal is attached, because PTY EOF nudges.
**Dissent to honour**: advocate-a conceded fully. The accepted cost is the ≤5 s stale-alive window with no terminal attached. The debate also found that no code path nudges a liveness check on `SessionEnd`, although `docs/protocol.md:1344` and `docs/features/lifecycle/spec.md` say one does. The doc edit removes that claim. Adding a real nudge on `SessionEnd` would narrow the 5 s window. That is a follow-up (proposed-backlog), not part of this decision.
**Landed in**: unit F3 (`plan.md`), `docs/protocol.md`, `docs/features/lifecycle/spec.md`, `plans/maintainability-cleanup/proposed-backlog.md`. No new ADR: the accepted ADRs already state the outcome, and F3 brings the code and protocol in line with them.
