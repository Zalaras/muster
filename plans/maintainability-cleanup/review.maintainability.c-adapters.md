## Issues

### Critical

None.

### Major

1. **[daemon-impl]** The subprocess run-func seam, which conventions § Testing names as the model ("Every subprocess call gets an injectable run func on the type that owns it … `internal/locate.SpotlightFinder`, `tmux`'s preflighter and its `Client`, `claudecode`'s `execFunc`"), comes in five shapes across the adapters, wired two opposite ways.
   - `claudecode/credentials.go:27` is an unexported `execFunc(ctx, name, args...) ([]byte, error)` returning stdout. The exported `KeychainTokenReader(user string, run execFunc)` takes it as a parameter.
   - `claudecode/modelcheck.go:34` is an exported `ModelCheckRun(ctx, dir, argv []string) ([]byte, error)` returning stderr, passed per call.
   - `ghissue/ghissue.go:53` is `execFunc(ctx, name, args...) (stdout, stderr string, err error)`.
   - `selfupdate/exeversion.go:27` is an anonymous `func(ctx, name, args...) (string, error)` passed per call.
   - `tmux/tmux.go:33`, `tmux/preflight.go:26` and `locate/spotlight.go:19` hold `[]byte` fields.

   Wiring differs too. tmux and locate set their production default inside their own constructor (`tmux.New` → `execCombinedOutput`, `NewSpotlightFinder` → `runMdfind`, both unexported). claudecode, ghissue and selfupdate export their production function so the composition root can pass it in (`internal/server/usage.go:77` `claudecode.RunCommand`, `internal/server/issue.go:519` `ghissue.RunCommand`, `internal/server/server.go:193` `claudecode.RunModelCheck`, `cmd/musterd/main.go:445` `selfupdate.RunVersionProbe`). Two exported functions share the name `RunCommand` with different signatures: `claudecode/credentials.go:32` returns `([]byte, error)`, while `ghissue/ghissue.go:57` returns `(string, string, error)`. The two package exemplars (`tmux/CLAUDE.md`: preflight.go, `locate/CLAUDE.md`: spotlight.go) show the constructor-default shape, and three sibling adapters do the other. A newcomer who learns one adapter's seam has to relearn it in the next, which § Design "Match the siblings" is meant to prevent. A fix must make true that the adapters share one seam convention: where the production default is set, whether the production function is exported, and one signature per output need (stdout, stderr, or both). It must also make true that no two exported production run functions share a name with different signatures. If the convention is not the tmux/locate shape, conventions § Testing must say which one it is.
2. **[daemon-impl]** The ingest route shape and the session environment variable each have two owners in two packages, with nothing at compile time linking them.
   - The route is registered at `internal/server/ingest.go:280-281` (`POST /ingest/{token}/hook`, `…/status`). It is rebuilt by string concatenation at `internal/claudecode/settings.go:277-278` and matched by regex at `settings.go:85`.
   - `MUSTER_SESSION` is set at `internal/server/sessions.go:182` and read by the generated script at `internal/claudecode/settings.go:306-308`.

   Renaming either side would compile, pass the unit tests of the package that changed, and silently stop every hook. This breaks § Design "One owner per concept … Two places that must agree will not". It also means claudecode holds Muster's own route and environment vocabulary, not Claude Code format knowledge (`claudecode/CLAUDE.md` "Owns: every Claude-Code-format fact"). A fix must make true that each of the two strings is declared once and every writer and reader references that declaration. The legacy-shape regex may stay as it is, since it matches historical entries, but it must be tied to the same declaration or documented as frozen history.
3. **[daemon-impl]** The "is a newer release available, and may this install apply it" logic is implemented twice. `cmd/musterd/update.go:59-78` runs `LatestTag` → `ParseRelease(tag)` → `ParseRelease(running)` → `Compare`, and `internal/server/update.go:269-284` runs the same sequence. The apply-eligibility rule of kb:adr/update-install-kinds-decide-who-may-apply is also written twice, in different forms: `cmd/musterd/update.go:48-55` enumerates `KindDev`, then `KindHomebrew || KindUnmanaged`, while `internal/server/update.go:398` tests `!= KindInstaller`. They agree today only because exactly four kinds exist. The tag's leading `v` is likewise rebuilt in server (`update.go:445`, `"v" + version`), although `selfupdate/CLAUDE.md` says selfupdate "Owns … semver comparison" and all release knowledge (kb:adr/update-release-knowledge-in-selfupdate-package). This breaks § Design "Reuse before add" and "One owner per concept". A fix must make true that the newer-than-running check, the may-apply rule and the tag⇄version mapping each live once in internal/selfupdate, and that cmd/musterd and internal/server both call it. The server half belongs to the server scope's V6/D7 unit, and the cmd half to D8.
4. **[daemon-tests]** `claudecodetest.go` holds near-duplicate builders.
   - `EnvelopedSessionStartTranscript` (`:238-269`) copies `EnvelopedSessionStart` (`:62-98`) line for line except `transcript_path`. Its own doc comment gives the reason as plan history ("kept separate … so this plan's own fixture need is additive"), which is not a reason a reader can act on.

A fix must make true that each wire skeleton (envelope, SessionStart payload, status-line payload) is built in exactly one place, that one default comes from one place, and that the two status-line builders take options the same way. The byte output of every existing builder must stay unchanged, since dedup tests depend on it (`:470-471`).
