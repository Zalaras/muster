# e1 — A card shows alive for up to 5 s after Claude exits (no terminal attached)

Origin: `plans/maintainability-cleanup/decisions/sessionend-alive-hint/decision.md` ("Dissent to
honour") and `plans/maintainability-cleanup/proposed-backlog.md` § "Nudge liveness on SessionEnd".
Decision B deleted the `KindDeathHint` alive write and accepted ≤5 s of stale `alive` with no
terminal attached. It named a liveness nudge on a non-clear `SessionEnd`, kept behind the `stopped`
guard, as the follow-up.

## Reproduced

Scratch daemon (dev build of `main` @ e3e59bad): own data dir, own tmux socket path (`-tmux-socket
/tmp/e1m.XXXX/t.sock`), `-on-exit kill`. A stub `-claude-bin` waits for a marker file and then
exits 0, so its pane closes. No real `claude` was run. Script
`/private/tmp/claude-501/-Users-damian-Documents-code-Projects-muster/a0c8bb9b-28f1-443b-b236-b7d961a1bf9a/scratchpad/e1/repro.py`:

1. `POST /api/sessions`.
2. POST an enveloped `SessionEnd{reason:"other"}` (with the real `musterSession` and `tmuxPane`) to `/ingest/<token>/hook`. This is what real Claude sends before it exits.
3. Make the stub exit.
4. Poll `tmux has-session` and `GET /api/state` every 50 ms. No `/ws/terminal` is ever opened.

```
$ python3 -I repro.py "$S"
launched 201 id 1 target muster-1:@0
alive before exit: True
SessionEnd POST 200 ; stub told to exit
t=0.09s pane gone (tmux has-session fails)
t=4.32s card alive=false
# two more runs:
t=0.01s pane gone (tmux has-session fails)
t=4.66s card alive=false
t=0.08s pane gone (tmux has-session fails)
t=3.59s card alive=false
```

The pane is gone in under 0.1 s, but `alive` stays true until the next 5 s poll tick (3.6–4.7 s here).
After the run, the daemon was stopped and the socket checked with `tmux -S … ls`: "no server running".

## Holds

Holds as written. The scope is any exit where no Claude terminal socket is attached (Tiles/Focus not
showing it, the dashboard closed, or a `/exit` typed through another client). With a socket attached,
PTY EOF already nudges (`internal/server/terminal.go:320`).

## Cause

The only on-demand liveness check is `Manager.Nudge` (`internal/session/liveness.go:145`). Its only
production caller is the Claude terminal pump's PTY-EOF path (`internal/server/terminal.go:320`).

A non-clear `SessionEnd` becomes `KindDeathHint` (`internal/claudecode/interpret.go:280-288`). The
state machine deliberately treats it as a no-op (`internal/session/machine.go:116-121`, per
kb:adr/lifecycle-liveness-from-pane-existence). The ingest worker applies it and returns
(`internal/server/ingest.go:169`), and nothing re-checks the pane. So the death is only found by
`pollLoop`'s next tick (`defaultPollInterval = 5 * time.Second`, `internal/session/manager.go:62`).

One design constraint for the fix: a single `Nudge` at ingest time would race. The SessionEnd hook
fires from the still-running process, and ingest is async (kb:adr/ingest-seq-assigned-at-ingest). The
pane can still exist when the worker handles the event. Whether Claude awaits the SessionEnd hook
before exiting is **not measured**: kb:fact/hook-await-per-event covers only Stop→SessionEnd, and
kb:fact/hooks-not-awaited-on-failure-exit covers the auth-failure exit.

The fix should therefore be a short **bounded follow-up**, not a one-shot nudge. On a non-clear
`SessionEnd`, re-check the pane at a short interval (say ~200 ms) until it is gone or a cap passes
(say ~3 s), each re-check through `checkOneLiveness(…, false)`. That keeps the `stopped` guard
(kb:adr/lifecycle-liveness-writes-stop-at-shutdown), and it is not a payload write of `alive`. A late
or straggler SessionEnd (pre-resume pane, `/clear`'s own `reason:"clear"` is excluded anyway) only
checks a live pane and does nothing.

## Proof

- **Level:** unit. This is liveness logic behind the `PaneChecker` seam, and the fake falsifies it deterministically. An ingest-level test against the real server is a poor fit: `Server.Start` runs the 5 s poll with no interval knob in `server.Config`, so a "within 1 s" assertion would pass by chance whenever a tick lands in the window.
- **File:** `internal/session/manager_test.go`, written by **daemon-tests**.
- **Name:** `TestApply_NonClearSessionEndEndsSessionPromptlyOnceThePaneDies`.
- **Setup:**
  - `newTestManager(t, st, pc, rec.record, withPollInterval(time.Hour))`, so no poll tick can rescue it.
  - `CreateSession` + `RecordLaunch("muster-1:@1", "%1")`, with `pc.setExists("muster-1:@1", true)`.
  - `mgr.Apply(ctx, id, "c1", nil, claudecode.StateInput{Kind: claudecode.KindDeathHint}, true)`. The pane still exists at this point, which models the hook beating the process exit.
  - Then `pc.setExists(..., false)`.
- **Failing assertion today:** `require.Eventually(func() bool { got, _ := mgr.Get(id); return !got.Alive }, 1*time.Second, 20*time.Millisecond)`. It fails because nothing re-checks the pane.
- **Companion assertions:**
  - `KindClearDeathHint` starts no watch: alive stays true within the same bound while the pane exists.
  - After `mgr.Stop`, a follow-up check does not persist `alive=false`. This mirrors `TestCheckOneLiveness_StoppedGuard_PeriodicPollAndNudgeSkipPersistAfterStop`.
- **If the trigger is placed in `ingest.go` instead:** the test calls the new manager method directly, with the same assertions. The ingest wiring is then covered by a small `internal/server` test with the session manager faked or with a fast check. It is still daemon-tests' work.

## Route

`fix`. There is no daemon↔UI protocol change: the same `sessionUpsert` with `alive:false` arrives
sooner. There is no new spec and no new UI surface. `docs/protocol.md` prose about what nudges
liveness changes (doc-reconcile), but no message, field or anchor does.

## Questions

None needed to proceed unattended. Two choices the batch can settle itself (no ADR reversed;
kb:adr/lifecycle-liveness-from-pane-existence already says "checked on a periodic tick and on
demand"):

- **Re-check interval and cap.** ~200 ms for up to ~3 s is suggested. Anything well under the 5 s poll fixes the symptom.
- **Where the trigger sits.** `Manager.Apply` on `KindDeathHint`, or the ingest worker after `Apply`.

The developer may want a measurement of how long after `SessionEnd` the real `claude` pane closes.
The bounded re-check makes that unnecessary for correctness.
