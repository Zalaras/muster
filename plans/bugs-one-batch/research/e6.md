## Holds

Did not hold. At all five viewport heights, the first attach gives the same results:
- The xterm rows equal the rows that fit the slot (`fitRows`).
- They equal tmux `pane_height`/`window_height`.
- They equal the settled value and the value after a resize round-trip.
- The first `resize` frame (+1–23 ms after the socket opens) already carries the settled row count, so there is no transient extra row and no missing row.

The terminal is not a row short, and it is not a row tall either.

## Cause

None, because the claim does not hold. The NBSP placeholder (`web/src/render/focusview.ts:42`) gives
`#sizenote` its real height (26 px, measured) before `features/focus.ts:255`'s first `refit()`. The first fit
therefore sees the final slot height: the leftover space is less than one 24 px cell at every measured height,
for example 598.63 − 576 = 22.6 px at 720.

There is one stale related comment: `web/e2e/terminal.spec.ts:211-221` (E4). It still says the first fit
measures the slot "at its pre-sizenote height (one row taller than its steady state)" and cites `main.ts:175`.
That was true in the ASCII-space era and is not true now. This is optional comment upkeep, not a fix.

## Proof

No test is red today. No current test pins the first-attach geometry. E4 (`web/e2e/terminal.spec.ts:190`,
"the tmux oracle's window geometry matches the terminal's own fitted size (E4)") polls until the sizenote and tmux
agree, so it accepts a wrong first frame that is corrected later. Unit coverage
(`web/src/render/focusview.test.ts`) checks the sizenote text, not the NBSP placeholder.

A guard would sit at two levels. It would be written by e2e-specs, plus web-tests for the cheap half:
- **Unit (web-tests)**, `web/src/render/focusview.test.ts`: `renderSizenote(el, null, { reserving: true })` leaves `el.hidden === false` and `el.textContent === " "`. This would fail if the ASCII-space regression from `a7ba245e` came back. It is the cheapest test that catches the known cause.
- **E2E (e2e-specs)**, `web/e2e/terminal.spec.ts`: "the first resize frame on Focus attach already carries the settled rows". It would record `framesent` resize frames and assert that the first frame's `rows` equals the settled sizenote rows and tmux `#{window_height}`. This asserts a protocol frame, not a display. Still, check it against `kb:adr/process-transient-displays-not-oracles` before adding it.
