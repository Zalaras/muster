# E2E re-levelling — 2026-10-20

Follows `test-audit-2026-10-19.md` (the sweep's time is harness floor around small
assertions) and kb:adr/process-test-levels-journey-property-logic (a test lives at the
cheapest level that can falsify its claim). Nothing moved when the rule landed; this audit
classifies every existing E2E test and moves the properties to the render tier
(`web/render/`, kb:adr/process-render-fixtures-generated-from-daemon) and the logic to Vitest.

## Method

One spec file per batch, largest floor-bound files first. Every test in the file is
classified **journey** (needs the daemon and the UI together — a launch, a hook or
checkout changing a card, resume, restart, kill, an API round-trip), **property** (what the
display shows for a given snapshot — layout, tokens, density, chords, widths, host views) or
**logic** (no DOM needed). A journey stays. A property becomes a render test in
`web/render/<feature>.spec.ts` against a fixture generated by `make gen-render-fixtures`; a
state no fixture held got a scenario in `internal/server/renderfix_scenarios.go`. Assertion
strength is kept: the same computed-property checks, the same widths, the same host views.
Each batch was gated with `make render-test`, `make web-test`, `make e2e SPECS='<file>'` and
`make check`, and committed as `test(<feature>): move display properties to the render tier`.

Shared DOM code moves with the properties: the render helper owns a feature's locators and
layout oracles, and the E2E helper re-exports them, so a locator is written once for both
tiers (`web/e2e/helpers/card-location.ts` → `web/render/helpers/card-location.ts`).

## Measurement

(b424daa2), nothing else running, 4 workers; the render tier the same way straight after.

The 387 tests that left E2E took the harness floor with them: the E2E sweep lost 947
worker-seconds and the render tier runs the same 391 claims (387 ports plus four
fixture-identity tests) in 455. Both tiers together take 1,518 worker-seconds and 399 s of
wall for 1,005 tests, against 2,010 and 523 s for 1,001; and the render tier holds the gate
lock shared, so it runs beside unit tests rather than after them.

What is left in E2E by duration: `update.spec.ts` (27 tests, 158 s — restart flows at
13–20 s each) is now a third of the sweep's tail; the rest is spread thin (the next nine
files total 379 s over 197 tests). The 487 tests under 2 s are 519 worker-seconds — still
floor, but every one of them now crosses the live seam for a reason its section names.

## Infrastructure changed on the way

- Fixtures record each session's reader listing and documents; the harness serves the
  reader's two GETs from them (kb:adr/process-render-fixtures-record-reader-documents,
  `proposed` on this branch — flip at land).
- Every generator step runs in its own wall-clock second and the repo's launch time is
  aligned to the session's createdAt (a launch is one instant on the wire), so
  `check-render-fixtures` is deterministic under load. Generation now takes ~50 s for 102
  scenarios; `make check` pays it.
- `claudecodetest` gained `SessionStartOpts.Cwd`, `StatusLineFullOpts.CurrentDir` and
  `AddedDirs`, `RawUserPromptSubmit`/`PromptSubmitOpts`; a renderfix-tagged
  `store.AlignRepoLaunchedAt`. Shared render helpers: `helpers/style.ts` (tokens, clipping),
  per-feature helpers that the E2E helpers re-export, so each locator exists once.

## Borderline, left in place — for the developer to rule on

Each batch's section lists its borderline tests with both readings. The recurring shapes:

1. **A view or pref switch inside the test** (focus, shortcuts, groups, usage, misc): the
   display on each side is a property a `withPrefs` fixture holds, but the test waits on the
   prefs broadcast. Kept as journeys; ~12 tests.
2. **A property plus the PUT/DELETE that follows it** (groups, rail-menu, actions, rename): the
   menu, dialog or copy is display, the chosen action is the daemon's. Kept whole; ~14 tests.
3. **A property proven after a hook changes state** (rail-cards, sessions, bypass INV-1,
   card-location E4 and the plain-directory move): kept as journeys; ~8 tests.
4. **Harness capabilities that would move more**: a context-level route for the pop-out
   (6 reader-find + 5 reader tests); `/api/browse` recorded per path (13 launch + 1
   launch-defaults + 1 bypass + 4 permission-mode); update states beyond dev/idle (5 update);
   `/api/past-sessions` recorded (6 past-sessions); the pane GET recorded (actions E6, Major 6's
   positive cap clause, terminal REQ-13); a way to withhold the hello or close the socket
   (the dot's colours, the pending dot, resilience's banner, three added-dirs/drop tests).
5. **Two "with the daemon down" tests** (launch-model-check REQ-10/E5, past-sessions E9) were
   ported and their E2E copies deleted — the same `{ok:false}` branch for a 404 and a dead
   daemon, with the connection-level failure held by launch's two `route.abort()` journeys. If
   the connection-level failure is held to be the claim, restore them from `main` before the re-levelling landed (2018bab6).
6. **Patterns to confirm**: usage pins the page clock with `page.clock.setFixedTime` at
   exact normalised instants (the E2E did the same with its own clock); the misc batch pushes a
   second fixture's recorded `prefs` or `snapshot` frame to reach Tiles or the done tick — fixture
   data, never hand-written, but a frame from another scenario.
7. **Vitest**: no batch found pure logic still tested only in E2E; every candidate matcher,
   parser and formatter already had unit coverage.

## Rulings — the developer, 2026-10-31

1. **View or pref switch inside the test** — stay journeys: the switch's round trip through the
   daemon is part of the claim.
2. **Property plus the PUT/DELETE that follows** — stay journeys: the action reaching the daemon
   is the claim.
3. **Property proven after a hook changes state** — stay journeys: the hook moving state is
   daemon behaviour.
4. **Harness capabilities that would move more** — not built now; the E2E speed work is closed
   for the time being. Revisit only if sweep time becomes a cost again.
5. **The two deleted "with the daemon down" tests** — not restored: a 404 and a dead daemon take
   the same `{ok:false}` branch, launch's two `route.abort()` journeys hold the connection-level
   failure, and the render tier holds the display.
6. **Patterns to confirm** — both accepted: a pinned page clock, and a frame recorded for
   another scenario (daemon-generated data, never hand-written).
7. **Vitest** — nothing to move.

Net: no test moves.
