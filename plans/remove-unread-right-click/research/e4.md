# e4 — Problem with overlap for new note (#106)

## Reproduced

Scratch render spec (outside the repo, scratchpad config pointing `testDir` at it, repo's
render harness/helpers imported by absolute path, built bundle from `internal/webui/assets`):

```ts
await dashboard.open("notes");
const card = railCardByTitle(page, "notes-short");
const marker = shownMarker(card.locator(".r2"));
await marker.hover();
await expect(noteTip(page)).toBeVisible();          // passes: the note tip opens
const inherited = await marker.evaluate((el) => {     // nearest ancestor-or-self title = Chrome's native tooltip
  for (let n: Element | null = el; n; n = n.parentElement)
    if (n.hasAttribute("title")) return { from: n.className, title: n.getAttribute("title") };
  return null;
});
expect(inherited?.title ?? "").toBe("");
```

The note tip (350 ms custom popover) is visible, and the marker inherits `.r2`'s native
`title` ("notes-short / main"), which Chrome shows ~1 s later on top of the tip.

## Holds

Held as written. The "file path and branch hover" is the browser's native `title` tooltip,
not a Muster popover. Tiles are unaffected: the tile header's `.mk` is a sibling of `.wh`
(which carries the title), not inside it.

## Cause

`web/src/render/sessions.ts:89` sets `repo.title = vm.repoLine` on the `.r2` block, and the
note marker `.mk` is a child of `.r2` (`web/index.html:429`; hover attached at
`web/src/render/sessions.ts:283`). A descendant with no `title` of its own inherits its
nearest ancestor's advisory title, so hovering the marker opens the note tip after
`POPOVER_DELAY_MS` (350 ms, `web/src/render/hovertip.ts:3`) and then Chrome's native tooltip
for `<repo> / <branch>` after its own ~1 s delay. Nothing delegated or timed in Muster code
fires it. Minimal fix: give the marker an empty `title` (`marker.title = ""` in
`applyRepoBlocks`, beside the `applyNoteMarker` call at `sessions.ts:90`). An empty `title`
attribute stops the ancestor's title being inherited, and `.r2` keeps its title over the
folder/branch lines, so the existing `.r2` title assertions (rail.spec.ts E13,
card-location.spec.ts:167) stay true. The same template serves the strip card, so this one
line covers both.

## Questions

There are two possible expected behaviours. (a) Keep `.r2`'s title and isolate the marker
with an empty title. This is one line, keeps the folder/branch tooltip over the folder,
branch and card gaps, and keeps the existing tests green. (b) Move the title onto `.rf`/`.rb`
so it fires only over the text. That means more churn in `repolines.ts`, the `.rb` is created
on demand, and it changes E13/card-location assertions. This research recommends (a). It
meets "the note should be isolated from it", so no question needs the developer unless they
specifically want (b).
