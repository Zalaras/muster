## Holds

Holds as written. The scope is bigger than it looks: unread is held by the daemon and nothing lets the client set it.

## Cause

`unread` is a daemon-owned field on the session row (internal/session/session.go:174, persisted at internal/store/session.go:114/357, sent as `unread` at internal/server/sessionwire.go:51, documented at docs/protocol.md:1317 and :1418). The daemon sets it at turn close into idle when no terminal client is watching (internal/session/apply.go:94). It is cleared by any transition out of idle (internal/session/session.go:321) and by `Manager.MarkSeen` when either surface attaches (internal/session/manager_rail.go:169). kb:adr/rail-unread-inferred-from-live-terminal-client chose option A, "no new endpoint", over option B, "the client clears through an explicit seen call". So no HTTP route can set or clear it. The protocol's INV says `unread ⇒ state == "idle"`, so "Mark as unread" only makes sense for idle sessions. The menu is built in web/src/features/railmenuitems.ts:53 `cardMenuItems` and web/src/features/railmenu.ts:51 `cardEntries`. Neither has a read/unread entry because there is no action to send.

### Protocol delta (settled at the stop — the batch implements this verbatim, nothing else)

The developer approved this protocol change for this sweep; it is the only one, and it adds only
(no `protocolVersion` bump, kb:adr/connection-protocol-bumps-only-on-shape-change).

- Route table, beside `PUT /api/sessions/{id}/pin`:
  `| PUT /api/sessions/{id}/unread | Mark a session read or unread (kb:anchor/sessions.unread) |`
- New section `<!-- kb:anchor sessions.unread -->` `### PUT /api/sessions/{id}/unread`, placed
  after `kb:anchor/sessions.pin`, modelled on it:
  **Auth**: UI cookie (401 `unauthorized`). **Request:** `{ "unread": true }` (`unread` required,
  boolean). → `204`, no body. `unread:true` sets the session's `unread` iff its `state` is `idle`;
  `unread:false` clears it in any state. Already in the requested state, or `unread:true` on a
  session that is not `idle` → `204` and no broadcast (the no-op the developer asked for; the
  `unread ⇒ state == "idle"` invariant holds). Otherwise the session is broadcast as one
  `sessionUpsert`. Persisted like the daemon-set flag (survives restarts). Errors:
  `400 invalid_request` (body not JSON / `unread` missing or not boolean), `404 unknown_session`.
- `unread` field wording (the session-row comment and the bullet list): add "or by
  `kb:anchor/sessions.unread`" to how it is set and cleared. Every existing setter and clearer is
  unchanged: attaching still clears it, leaving idle still clears it. A hand-set unread on the
  session shown in Focus therefore stays until that session's next attach (the developer: "Correct").
- No batch route: the several-selected menu calls the per-session route once per selected id.
- A new ADR (accepted at Completion) amends kb:adr/rail-unread-inferred-from-live-terminal-client:
  inference from attach stays the default; an explicit user mark through this route is added.

Implementation notes the research already fixed: daemon setter beside `MarkSeen` in
