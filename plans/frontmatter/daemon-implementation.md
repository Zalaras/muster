## Decisions

- REQ-8: implemented entirely in `scanPlan` (see D7 below) — `Manager.SetPlan` is untouched.
- REQ-9: no code change; already enforced by `SetPlan`'s `claudeSessionID` comparison, unaffected by this change (a straggler's `claudeSessionID` still won't match the current binding, so its scan result — retained-or-found — never persists).
- Doc comments: only `scanPlan`'s own doc comment said "no plan yet" semantics that changed; `Manager.SetPlan`'s comment ("path == \"\" is the wire plan:null") and `Session.PlanPath`'s field comment are still accurate as descriptions of what `SetPlan` itself does — the retention decision is made by its caller before the call, so neither needed editing. Checked by reading both (`internal/session/manager.go:992-996`, `internal/session/session.go:111-115`).
- design: no new type, module or seam — this is a five-line change inside an existing function, matching the plan's own framing ("the daemon-impl agent may put it in `scanPlan` or in `Manager.SetPlan`"). Chose `scanPlan` because the retention question ("what did *this scan* find") is specific to the transcript-scan trigger; `SetPlan` is a generic setter also called from `observeWrite`'s exists-flip, where "found nothing" has no meaning. `rg -n "SetPlan\(" internal/server internal/session` shows `SetPlan`'s only other caller is `observeWrite` (the exists-true flip on a routed write to the known plan path), which always passes a real path — confirms `SetPlan` has no other planless-scan caller to worry about.
- No REQ in the plan's daemon scope (REQ-8, REQ-9) was left undone.
- No `doc-delta:` beyond what the plan's own Doc Delta section already states — `docs/protocol.md`'s `plan` comment was merged at plan approval (already reflects the sticky-once-named semantics, verified by `grep -n "never null again" docs/protocol.md`); `docs/features/reader/spec.md`'s "Locating the plan" sentence is the doc-reconcile step's job per the plan, not mine to pre-empt.

## Fix Attempt 1 (review cycle 1)

**Failures addressed**:
- correctness Major 1 — four daemon doc comments still described the pre-REQ-8 "null when the latest transcript names none" semantics.
- maintainability Major 1 — `scanPlan`'s retain-or-replace decision was a check-then-act split across two separate `Manager.mu` acquisitions (`Get`, then decide, then `SetPlan`), reachable from two goroutines (the ingest worker via `Observe`, and every `GET /api/sessions/{id}/reader` handler goroutine via `handleReaderList`), so a planless scan racing a concurrent plan-naming scan could clear or revert a plan that was set after the racing scan read its retained value.

**Changes made**:
- `internal/session/manager.go`: added `Manager.ApplyPlanScan(ctx, id, claudeSessionID, foundPath string) (*Session, bool, error)`, placed directly after `SetPlan`. It is now the **only** place the sticky-once-named retention rule (`kb:adr/reader-plan-sticky-once-named`) is decided, replacing the decision that used to live in `internal/server/reader.go`'s `scanPlan`. Everything happens inside one `m.mu.Lock()`/`Unlock()` critical section: the straggler gate (`sess.ClaudeSessionID != claudeSessionID`), the retain-or-replace decision (`path := foundPath; if path == "" { path = sess.PlanPath }` — reading `sess.PlanPath` from the live, currently-locked session, never a value cached from an earlier `Get`), the `os.Stat` that re-derives `exists` against whichever path is in play, the unchanged-short-circuit, and the write (`sess.PlanPath = path; sess.PlanExists = exists`) — all before the single `m.mu.Unlock()`. Persist (`m.store.UpdateSession`) and broadcast happen after unlock, matching `SetPlan`'s existing pattern (I/O never holds the lock beyond the one `os.Stat`, which is a local syscall, not network I/O). Added `"os"` to the file's import block (previously unused there; `SetPlan` never needed it because it never derives `exists` itself, callers always pass it in).
  **Where the stat runs relative to the lock**: inside it — the `os.Stat(path)` call sits between deciding `path` and the write of `sess.PlanPath`/`sess.PlanExists`, under the same `m.mu.Lock()` acquired at the top of the function. This is the change from the old code: previously the stat ran *outside* any lock, after a `Get`/`Unlock` had already released the mutex, which is exactly the gap the race lived in.
  `SetPlan`'s doc comment gained one sentence pointing callers that already know the real path (i.e. `observeWrite`'s exists-true flip, its one remaining caller) to keep calling it directly, and pointing a transcript scan that may find nothing to `ApplyPlanScan` instead.
- `internal/server/reader.go`: `readerManager` interface gained `ApplyPlanScan(ctx, id, claudeSessionID, foundPath string) (*session.Session, bool, error)`. `scanPlan` no longer calls `f.manager.Get` or does its own `os.Stat`/retention branch at all — it now only runs `claudecode.LocatePlanFile` and hands `pf.Path` straight to `f.manager.ApplyPlanScan`, unconditionally (`pf.Path == ""` for both "transcript missing" and "transcript names no plan", matching `ApplyPlanScan`'s `foundPath == ""` contract). `scanPlan`'s own signature (`ctx, sessionID, claudeSessionID, transcriptPath`) is unchanged, so `TestScanPlan_StickyOnceNamed` and every other caller of `srv.reader.scanPlan(...)` in `reader_test.go` needed no changes. Doc comments on both `scanPlan` and `SetPlan`/`sessionWirePlan`/`sessionWire.Plan`/`Session.TranscriptPath`/`SessionRow.TranscriptPath` rewritten (next item).
- Doc comments restated per correctness Major 1, each now saying "null until a transcript has named a plan; once set, a planless scan keeps it" (or the field-specific equivalent) and citing `kb:adr/reader-plan-sticky-once-named`:
  - `internal/server/sessionwire.go:35-38` (`sessionWire.Plan`)
  - `internal/server/readerwire.go:36-38` (`sessionWirePlan`)

**Decisions**:
- design: retention rule now lives in exactly one function — `Manager.ApplyPlanScan` (D7 still satisfied; moving it from `scanPlan` to the Manager was explicitly allowed by the plan and asked for by maintainability Major 1). `scanPlan` in `internal/server/reader.go` is now a thin translator: run the transcript scan, hand the raw result to the Manager. No other function reads-then-writes `PlanPath`/`PlanExists` for the planless-scan case; `SetPlan` remains a plain unconditional setter with its own straggler gate, used only by `observeWrite`, which never needs the retention rule (grepped above).
- design: `os.Stat` for the re-derived `exists` now runs inside `Manager.mu`'s critical section rather than outside it. This is the deliberate trade the fix makes: a local filesystem stat (not network I/O) blocking other `Manager` operations for its duration, in exchange for eliminating the read-decide-write gap entirely rather than attempting a compare-and-swap/retry scheme outside the lock. Given Muster is a single-user, local-disk personal tool and `SetPlan`/other Manager methods already do no I/O under the lock (they release before `m.store.UpdateSession`), this is a bounded, one-off cost during a transcript scan, not a hot path.
- No new `deviation:` from the plan — D7 ("retention rule in exactly one function, named in Decisions") is satisfied by naming `Manager.ApplyPlanScan` here; the plan already sanctioned moving it out of `scanPlan`.
- No new `doc-delta:` — the four comment rewrites are code doc comments, not `docs/` prose; `docs/` and `plans/frontmatter/plan.md` were left untouched per this wave's instructions.
