# Decision: envelope-pane-corroboration

**Outcome**: B — Strict. An enveloped event routes only when its `tmuxPane` is present and equals the session's stored pane; an absent or mismatched pane is persisted unrouted (NULL `event.session_id`) and logged. Every enveloped fixture helper takes the pane explicitly (e2e: a `daemon.tmuxPaneId(tmuxTarget)` helper querying `list-panes -F '#{pane_id}'` on the scratch socket, memoised per target; Go: the seeded pane), and every enveloped call site states it. No protocol change.
**Reached by**: consensus (advocate-a conceded in turn 2)
**Decisive argument**: Option A cannot keep the fake `%12` default, because it would mismatch every real scratch-socket pane, so A has to flip both fixture defaults to *no pane*. That routes all 123 enveloped e2e call sites and 26 `claudecodetest` bodies through the uncorroborated branch and leaves the new check load-bearing in exactly two tests. Advocate-b: "`docs/conventions.md` § Testing binds fixtures to 'the shapes the fact records measured', and the measured managed shape carries a pane — `kb:fact/command-hooks-inherit-pane-env`'s guard asserts `tmuxPane` on the interactive `SessionStart`. A's new default is the headless-probe shape, which the product never sends from a managed session." A's cost objection fell to measurement: ~10 ms per `list-panes` query, ~1.7 s across the run uncached, one query per session when memoised.
**Dissent to honour**: None on the outcome. One implementation hazard both sides agreed on: `internal/server/sessions.go:271` spawns the pane and `:288` records it, so a `SessionStart` arriving in that window meets an *empty* stored `TmuxPane`. Strict must treat an empty stored pane as "cannot corroborate — route on `musterSession` alone", never as a mismatch, or it drops the binding event. Advocate-a also corrected the record: no enveloped fixture site passes a pane today; the 169 count was inflated by import lines, 123 is the call-site figure.
