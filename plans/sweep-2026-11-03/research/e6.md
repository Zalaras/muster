### The order today, for each variant (`|` = separator; "Move to" is a non-focusable header)

One builder, `cardEntries` (`web/src/features/railmenu.ts:51-66`), serves the rail card, the Tiles
strip card and the Focus header's Session actions ⋯ (`focus.ts:160` → `railMenu.open`).
`openSelection` (`:80-103`) serves a selected card in Select mode.

| Variant | Today | After the fix |
|---|---|---|
| Live card | Stop…, Remove… \| Move to: groups…, New group…, \| No group \| Pin/Unpin \| Mark as read, Mark as unread | Stop…, Remove… \| Pin/Unpin \| Mark as read, Mark as unread \| Move to: groups…, New group…, \| No group |
| Ended, resumable | Resume, Remove… \| Move to … No group \| Pin/Unpin \| marks | Resume, Remove… \| Pin/Unpin \| marks \| Move to … No group |
| Ended, no Claude id | Remove… \| Move to … No group \| Pin/Unpin \| marks | Remove… \| Pin/Unpin \| marks \| Move to … No group |

| Select mode, unselected card | the single-card menu (rows above) | same |
| Tiles strip card / Focus header ⋯ | the single-card menu | same |

Destructive items: Remove… (the only `danger` item) and Stop… sit at the **top**, not last. So
moving Move to to the bottom does not put it below a destructive item; Remove… stays second.

## Holds

Holds as written, in every variant above: the Move to block (header, groups, New group…, No group)
is the second block, above Pin/Unpin and the two marks. Not a bug: it is the order the accepted
ADR records (see Cause), so this is a deliberate-order change, matching the `enhancement` label.

## Cause

`web/src/features/railmenu.ts:51-66` (`cardEntries`) concatenates actions, separator,
`deps.groups.moveToEntries(...)`, separator, Pin, separator, marks; `railmenu.ts:94-100`
(`openSelection`) does actions, separator, Move to, separator, marks. The Move to entries
themselves come from `web/src/features/groups.ts:392-426` (header, groups in rail order, New group…,
separator, No group) and need no change. The order is written down in the accepted
kb:adr/rail-card-menu-offers-remove-and-marks-whatever-the-state ("Stop… (live) or Resume …, then
Remove…, Move to, Pin or Unpin, then Mark as read and Mark as unread"; selection: "Stop…, Remove…,
Move to, and the two marks") and in `docs/features/rail/spec.md:37-38`. It was inherited from
kb:adr/rail-card-right-click-menu-holds-session-actions (superseded), where Move to came before Pin;
the marks were appended at the end in remove-unread-right-click. No record gives a reason for
Move to's position.

## Answers

Developer, 2026-11-03, verbatim: "6. Unread, Read | Stop/Resume, Remove | Pin | Move To. If I can sneak it in can you also make Unread/Read toggle like Stop/Resume depending on current state or is that a bit too much?"

Resolved (the orchestrating session answered "not too much" in the stop; web-only, the session already carries `unread`):
- Single-card menu order (rail card, Tiles strip card, Focus header ⋯): [read toggle] | Stop… or Resume, Remove… | Pin/Unpin | Move to: groups, New group…, No group. Items absent for a state are simply omitted (e.g. an ended card with no Claude id: [toggle] | Remove… | Pin | Move to).
- The read marks become ONE toggling item like Stop…/Resume: "Mark as read" when the session is unread, "Mark as unread" when it is read. This reverses the "(B) two fixed items always shown" choice in kb:adr/rail-card-menu-offers-remove-and-marks-whatever-the-state (developer, 2026-10-26) in favour of its option A.
- Selection menu (Select mode, right-click on a selected card): [toggle] | Stop… (any live), Remove… | Move to. The toggle reads "Mark as read" when any selected session is unread, otherwise "Mark as unread" (mirrors Stop… "when any is live"); it still sends one per-session request per selected id.
- One new ADR superseding kb:adr/rail-card-menu-offers-remove-and-marks-whatever-the-state, restating everything else in it unchanged (Remove on live, disabled while disconnected/busy, selection behaviour). The rail spec sentence on order is updated by reconcile.
