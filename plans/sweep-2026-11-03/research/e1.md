# e1 — Sessions survive only one daemon start after their tmux server is gone

## Reproduced

I built a scratch daemon from `main` @ 1a18a071 into the scratchpad. It ran with its own `-data-dir`, its own tmux socket path (`-tmux-socket /tmp/e1r.XXXX/t.sock`), `-port 18947`, `-on-exit leave` and `-open=false`. A stub `-claude-bin` ran `exec sleep 100000`, so no real `claude` started. The script is
`/private/tmp/claude-501/-Users-damian-Documents-code-Projects-muster/bd3ae956-8ab1-4add-a18a-407158a14d2d/scratchpad/e1/repro.sh`. It does the following:

1. Launches two sessions through `POST /api/sessions`.
2. Sends SIGTERM to musterd and kills the tmux server on that socket. This models a computer restart, or a crash that took tmux with it.
3. Starts musterd, then starts it again with nothing changed in between.

At each step it prints `GET /api/state` and the daemon's `reconciled sessions` log line.

```
$ repro.sh $S
== start 1: launch two sessions
  POST /api/sessions alpha -> 201
  POST /api/sessions beta -> 201
  rail: [(1, 'alpha', 'alive'), (2, 'beta', 'alive')]
== stop musterd (-on-exit leave), then kill the tmux server (models a computer restart / crash)
  tmux ls: no server running on /tmp/e1r.uXjH/t.sock
== start 2
  rail: [(1, 'alpha', 'ended'), (2, 'beta', 'ended')]
  reconcile log: kept_alive=0 marked_ended=2 shells_killed=0 swept=0
== start 3 (no other change)
  rail: []
  reconcile log: kept_alive=0 marked_ended=0 shells_killed=0 swept=2
  final tmux ls: no server running on /tmp/e1r.uXjH/t.sock
  no scratch daemon left running
```

The ANSI colour codes in the log line are stripped above. Start 2 keeps both sessions as ended, resumable cards. Start 3 deletes both rows (`swept=2`), and the rail is empty.

## Holds

**Holds as written, but it is not a code defect.** The code does exactly what the design says. The sweep is a deliberate, user-decided rule:

- kb:adr/lifecycle-ended-rows-swept-next-start chose option C with the developer: "rows already ended are deleted … every death gets one resume chance". It is now superseded.
- kb:adr/lifecycle-reconcile-converges-with-the-socket is **accepted** and restates that rule unchanged: "A row whose `muster-<id>` is absent follows the superseded rules exactly."
- `docs/protocol.md:1893-1898` and `docs/features/lifecycle/spec.md:146-148` describe the same rule.
- `web/e2e/reconcile.spec.ts` E4 asserts it.

Fixing this bug therefore **reverses an accepted ADR's sweep clause**.

The scope is wider than "after their tmux server is gone". Every start deletes **every** row that was already ended when it began, however the row ended:

- the pane died while musterd was down (this entry);
- the user pressed End;
- Claude exited on its own while musterd ran;
- `-on-exit kill` ended it at shutdown. That row gets **zero** surviving starts: E4 asserts it is gone at the very next start.

An Update & restart (kb:adr/update-restart-is-in-place-reexec-not-shutdown) re-executes musterd. `Reconcile` runs again (`internal/server/server.go:264`), so an update counts as a start too. One update after a reboot clears the rail.

**#47 (e2) is the same defect.** The developer stopped musterd and killed tmux, and the issue's snapshot shows `0 sessions`. The sessions had their single ended lifetime and were swept at a later start. That later start could have been a second `make run` or an update re-exec. #39 (Archive, Post v1) is where a future auto-clear policy would live.

## Cause

`internal/session/reconcile.go:123-127` (`classifySessionsByOwnership`) checks each row whose `muster-<id>` is absent from the socket. If the row has `alive=true`, it goes to `toEnd`. If it has `alive=false`, it goes to `toSweep`. `actOnReconcile` (`reconcile.go:87-96`) then calls `removeSessionRecord(ctx, id, false)` for each swept id, which deletes the row from the store and from memory. The rule is documented at `reconcile.go:31-34`: "absent, row alive=false → swept (deleted; already had its resume chance in an earlier daemon lifetime)". A start marks a dead-pane row ended (`markEnded`). The next start then finds `alive=false` and deletes it. Nothing records *why* a row ended, so reconcile cannot tell a crash death from a deliberate End.

## Questions

1. **Reverse the "one resume chance" rule?** The developer settled in planning (m4-reconcile, option C) that a start deletes rows already ended, "a fresh start keeps the UI clean". This entry says "a crash must not clear sessions". Confirm the new rule supersedes kb:adr/lifecycle-reconcile-converges-with-the-socket's sweep clause.
2. **Which ended rows does a start keep?** This is a choice between fixes:
   - **A. Keep every ended row until Remove.** Reconcile never deletes. This is the smallest change: no migration, only the sweep branch removed. The rail accumulates ended cards until they are Removed by hand, with bulk Remove via select mode. Auto-clearing is left to #39 Archive.
   - **B. Keep only rows that died without the user asking.** That means rows marked ended by reconcile (the tmux server gone) or by the liveness poll (the pane died). A start still sweeps rows the user ended: End, or `-on-exit kill`/`y`. This needs a persisted end cause (migration 0019 + store-schema diagram). It also needs a ruling on Claude's own `/exit` while musterd runs, which the poll sees as a pane death. kb:fact/sessionend-reason-ambiguous means Muster cannot tell `/exit` from a crash.
   - **C. Age-based.** A start sweeps ended rows older than N days. This needs N, or a setting, and overlaps #39.

   My recommendation is A. It matches #47's "should come back on restart as resumable rows" and the entry's wording. It reverses nothing besides the sweep clause, and #39 already owns cleanup policy.
3. **`-on-exit kill` (E4)** is a consequence of 2. Under A, a session killed at shutdown comes back as an ended, resumable card instead of vanishing. Confirm that this is wanted. The alternative is to keep the old behaviour for kill only, which is a narrow form of B.

## Cleanup

Each run created its data dir and tmux socket under a fresh `/tmp/e1r.XXXX` and deleted the whole directory at the end. Every run ended with `tmux -S <sock> ls` reporting "no server running", and the scratch daemon was stopped with SIGTERM and waited on. After the runs:

- `ls -d /tmp/e1r.*` matched nothing.
- `pgrep -fl scratchpad/e1/musterd` reported "no scratch musterd".
- `pgrep -fl stub-claude` reported "no stub claude".

The real data dir and the `muster` socket were never used, and no real `claude` was run.
