## Decisions

- Reviewed against REQ-1/REQ-2 and the Reviewer-Verified bullet: `alive` is never written from the payload; the only flip path is `checkOneLiveness` -> `markEnded`. The goroutine returns at the 3 s deadline, when `m.stopped` is set, when the session is unknown or has no target, or once `Get` shows `!Alive`. A live pane makes each pass a snapshot capture and nothing else (edge case 2 expires at the cap).
- Measured: `TestApply_NonClearSessionEndEndsSessionPromptlyOnceThePaneDies` passes its `require.Eventually` in about 0.23 s on every run (1 s budget); `TestApply_ClearSessionEndStartsNoPaneRecheck` and `TestApply_SessionEndRecheckDoesNotPersistAfterStop` pass (0.73 s each).
- design: re-check is a method on `Manager` beside `Nudge` and `checkOneLiveness`, not a new type; it matches `Nudge` in running detached from the request ctx (`context.WithoutCancel`) and off `m.wg`, so Stop does not wait on it and the `stopped` guard is what silences it. Guard owner is `m.stopped` (writer: `Stop`; readers: `checkOneLiveness`, this loop). Timers are local to the goroutine; no shared state added.
- design: `rg 'TmuxTarget' internal/session/*.go` found only the inline read in `Nudge` and the `checkLiveness` closure; `tmuxTargetOf` is that `Nudge` read extracted so the watch and `Nudge` share it (Nudge's behaviour unchanged).
- design: two SessionEnds in a row start two watches; each is bounded by its own 3 s cap and ends when the pane is gone, so no dedupe set was added (it would be shared state needing a guard for no observable gain).
- design: the plan's Implementation hint to track the goroutine on `m.wg` or a manager context was dropped: Stop must not block on a 3 s loop, and the post-Stop re-check is made harmless by the `stopped` guard, as for the PTY-EOF `Nudge`.
- design: `reader-docs-large-pair` mirrors `driveReaderDiagramsPair`'s two-session loop without the tiles pref, using `readerLargeDocs()` for both sessions.
- test-race: `TestApply_NonClearSessionEndEndsSessionPromptlyOnceThePaneDies` is flaky at `manager_test.go:975` (`assert.False(t, persisted.Alive, "the flip is persisted, not just in memory")`) and `manager_test.go:978` (`assert.False(t, all[len(all)-1].Alive, "the same sessionUpsert carries alive:false to dashboards")`), never at the `require.Eventually`. Measured with `go test -count=10 -run TestApply_NonClearSessionEndEndsSessionPromptlyOnceThePaneDies ./internal/session/`: 7 pass, 3 fail. Cause is in the test: it polls `Manager.Get`, which sees the in-memory flip `markEnded` makes under `m.mu`, then reads the store and recorder while `persistWholeRowLocked`'s store write and broadcast are still in flight under the write ticket (`internal/session/writeorder.go`), the same order the PTY-EOF `Nudge` path has. Not changed: persisting before the in-memory flip would deviate from the write-order ADR. Fix belongs in the test: poll `st.GetSession(...).Alive` and `rec.all()` inside the `Eventually` instead of `mgr.Get`.

**Paths to the Minor 2 defect, and how each is closed**:
- Watch pass in flight when `Stop` runs: `Stop` cancels `runCtx`, so the pass's `checkCtx` is cancelled and its `PaneExists` / capture / store calls fail at once; `Stop` waits on `wg`, so the pass has returned before `Stop` does. No snapshot is stored after `Stop` returns (this also closes code Note 1 for the watch).
- Watch idle between ticks: `select` returns on `ctx.Done()`.
- `Apply` arriving after or during `Stop`: `spawn` checks `stopped` under `spawnMu` and starts nothing; `Stop` sets `stopped` under the same mutex, so no `wg.Add` can race `Stop`'s `Wait`. This was the real reason the old code stayed detached; it is now handled instead of avoided.
- `Start` after `Stop`: starts nothing (same `spawn` check); `Start` itself was already on `wg`/`cancel`, now through the same helper.
- Zero-value `Manager{}` (test only, `manager_writeorder_test.go`): never calls `Start`, `Stop` or `spawn`; `Stop` keeps its nil-`cancel` tolerance.

**Blast radius** (`rg 'm\.cancel|\.cancel\b|\.wg\b' internal/session`): only `liveness.go` (`Start`, `spawn`, `Stop`) and the new `NewManager` assignment read or write them; `Stop` callers (server shutdown, tests) now also wait for the watch, bounded by the same ctx deadline.

**Decisions**:
- design: `spawn` is one helper on `Manager` beside `Start`/`Stop`, started by `rg 'go func|m\.wg' internal/session` finding only `Start`; it generalises that one goroutine start rather than adding a second pattern. Shared state: `stopped` (writer `Stop`, under `spawnMu`; readers `spawn`, `checkOneLiveness`, the watch), `spawnMu` (guards the stopped-flip against `wg.Add`), `runCtx`/`cancel` (written once in `NewManager`, read-only afterwards).
- design: `driveReaderPair` takes `[2]string` names and a docs func and returns the scenario drive func, the shape `withPrefs` already composes with. `rg 'driveReader.*Pair'` found the two copies this replaces.
- Not changed, per the review notes: the per-pass `endRemoveTmuxTimeout` (5 s) bound stays, since cancelling `runCtx` already ends any pass at once (maintainability Note 1).
- No `deviation:`; doc-delta: none. The earlier design line about the watch being off `m.wg` is superseded by this section.
