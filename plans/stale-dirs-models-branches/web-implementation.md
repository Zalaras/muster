## Decisions

- Testable UI Elements: every row is implemented as written. `.r2 .rf`/`.rb`, `.r2c` (`.lead` `↳`), `#mainhead .meta .loc .repo`/`.claude-at`/`.model`, `.thead .wh`/`.wh-claude`, and the `title` attributes all exist at the stated selectors. Measured by the plan's own spec (see Handoff).
- The `↳` block's `.rb` is the bare branch, with no ` (worktree)` marker (`claudeLocationParts` passes `markWorktree: false`). REQ-12 and the Testable UI Elements table list `<location branch>`, the launch readout is the only one that is flagged, and `card-location.spec.ts` asserts `worktree-e7b`. The first spec run failed on this (`Received: "worktree-e7b (worktree)"`) before I changed it.
- `locationHover` and `claudeHover` return `\n`-joined strings (not arrays), matching the `title` they are written to. W3 should assert strings.
- Consequence of REQ-17: the Focus header's `button.rename` `title` is now the session title, so the "Rename · clear to use Claude Code's name" hint it used to carry (index.html) is gone there. Tiles keep it (`render/tiles.ts`). `rg "clear to use Claude" web/e2e web/src docs/features docs/design` found no test or doc that asserts it on the mainhead.
- Hidden-attribute sweep: elements this change toggles with `.hidden =` are `.r2c`, `.claude-at`, `.loc > .sep`, `.ended-at`, `.wh-claude`. `.r2c` and `.claude-at` carry a `display: grid` rule and a `[hidden] { display: none; }` companion. The compact rail rule that sets `.r2c { display: flex }` is `:not([hidden])`-scoped. The other three declare no `display`. Measured in the built CSS: `{"r2c":[true,"none"],"claudeAt":[true,"none"],"locSep":[true,"none"],"endedAt":[true,"none"],"whClaude":[true,"none"]}` (`[hidden, computed display]`).
- Computed measurements against the built CSS (Chromium, 1280x800, 57-char folder, 80-char branch): Focus `.rf` clientWidth 203 and `.rb` 298 (30ch and 44ch at 11.25px mono), both clipped (`scrollWidth` 406 and 542); `.model` right 1066 vs `.meta` right 1066, `scrollWidth` 68 = `clientWidth` 68; `.lead` colour `rgb(178, 182, 195)` = `--fg-muted`, `.rf`/`.rb` `rgb(166, 171, 188)` = `--fg-dim` (Instrument), `rgb(65, 69, 79)` and `rgb(73, 77, 92)` (Light). The plan's E11 and REQ-16 specs also passed in the real app.
- Memo/reuse inputs: no reuse cache was added. `renderRepoLines` mutates the existing `.rf` and `.rb` text nodes; the only node created or removed is `.rb`, a non-focusable readout, when `branch` flips between null and non-null. The mainhead `button.rename` keeps its node (the plan's focus-survival spec passed).
- design: `render/repolines.ts` is a new module in `render/`, the shape of its neighbour `context.ts` ("one builder, two renderers"): it takes an already-computed `RepoParts` and does DOM only. Precedent check: `rg -n 'replaceChildren|\.rb\b|renderRepo' web/src/render` found no existing two-line repo builder; `renderContextRow` is the structural match.
- design: `RepoParts`, `MainheadMeta`, `claudeLocationParts` and friends live in `sessions/card.ts`, not `features/`, because they derive from session data and `card.ts` is the module `sessions/CLAUDE.md` names as the view-model exemplar. `mainheadMeta` keeps its name with a new return type, so its one caller (`render/mainhead.ts`) and `render/CLAUDE.md`'s "strings come from `card.ts`" rule are unchanged. `repoLine` stays as the one-line form (tile `.wh`, actions dialog copy, rail hover) and is built from `repoParts`, so the two cannot drift.
- design: `.meta` is static markup in `index.html` updated in place, matching how `renderMainhead` already treats `.chip-danger` and the action buttons (`requireElement` per slot, no field per slot on `MainheadElements`). The `!session` branch used to clear `metaEl.textContent`, which would now detach the static slots, so it no longer touches `metaEl`; the root is hidden and the next focused pass overwrites every slot.

- design: the compact rail rows use flex (`.r2`, `.r2c`), not inline boxes. With inline children the branch's box ran past `.r2` while the text was clipped; flex items each ellipsize within the card (the plan's `rbInsideR2` assertion needs the box itself inside `.r2`).

## Fix Attempt 5 (review cycle 4, made by the orchestrator at the developer's instruction)

Cycle 4 browser Minor 1 / correctness Major 2: `.loc` kept room it did not show — a `↳` block that gave way beside a whole title (up to 83 px), and a folder line under the 8-character floor (20.3 px for `api` / `main`). **Decisions**:
- design: a JS fit (`fitMainheadMeta`) trims `.loc`, because CSS cannot: `.loc`'s width follows the window continuously while the `↳` block shows or hides whole, so some band of widths always holds room for a block that is not drawn, and CSS has no `min(8ch, max-content)` for the floor. The fit clears `--loc-cap`, measures whether the `↳` block is on `.loc`'s first line, and, if not, sets `--loc-cap` to the repo block plus its `·` room; style.css caps `.loc`'s `max-width` and the grid track's minimum with it, so the leftover goes to the title or the header's free space. Measured with the cap cleared every time, so the decision never feeds on its own result (render-state rule: no cross-call state). It runs at the end of every `renderMainhead` pass and from a `ResizeObserver` on the Focus pane (`section.main`, `flex: 1; min-height: 0`): the pane's size never depends on the header, so refitting cannot loop. Precedent check: `rg -n 'ResizeObserver' web/src --glob '!*.test.ts'` found none before this; it is the first, scoped to the one header that needs a measurement. The test doubles in `render/mainhead.test.ts` gained a `style` and a null `offsetParent` (not laid out), so the fit returns early there; the trim itself is asserted against real layout in `web/e2e/card-location.spec.ts`.
- Red proof: the 66 Focus-header tests against the pre-fix product files gave 20 failures (tiny names: `.loc … is 20.3px wider than its visible blocks`), and 66/66 with the fix. Full gates after: 22 lines, 0 failed, 603 e2e passed.
- deviation: none (the plan's decisions A and B stand; the fit only removes unshown room).
